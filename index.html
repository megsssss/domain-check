Product notes

Problem
Asking a broker for a price means asking blind. Buyers can’t tell whether a quote is fair, so some give up before the first message. This is an assumption to validate in buyer interviews.
Hypothesis
If buyers see why a domain is valued the way it is, and can send a qualified enquiry in under a minute, more of them will enquire and brokers can skip the basic questions in the first reply.
Metrics
  • North Star: enquiry-to-deal conversion
  • Evaluation to enquiry-start rate, and enquiry completion rate
  • Time to first broker response
  • Guardrails: share of low-quality enquiries, complaints about score accuracy
Next steps
Interview 5 to 8 buyers, replace the rule-based score with comparable-sales data, and A/B test a shorter enquiry form.

How I built it

Approach
I started from one buyer problem, not knowing whether a price is fair, and picked the smallest flow that tests it: evaluate a domain, then enquire. Everything else was cut.
Stack
One HTML file with plain HTML, CSS and JavaScript. There is no framework, backend or database, so it loads instantly and can be hosted anywhere for free.
Scoring
Five factors add up to 100: length (25), extension (20), easy to say and spell (20), clear meaning (20) and memorability (15). Clear meaning checks the name against a small list of common business words. The price band is a lookup from the score.
Enquiry flow
Three tap-to-answer questions plus an email, with error messages that say how to fix the problem. Answers are pills instead of dropdowns so the form is quick on a phone.
Limits
The score is rules-based, the word list is small, there is no real sales data, and enquiries are not stored or sent. A live version would use comparable sales and route each enquiry to a broker queue.
